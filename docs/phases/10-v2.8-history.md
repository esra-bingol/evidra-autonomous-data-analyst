# Aşama 10.8 — Durable Investigation History (V2.8)

**Proje:** Evidra  
**Önceki:** [10-v2.7-dataset-adapter.md](10-v2.7-dataset-adapter.md)  
**Sonraki:** [10-v2.9-limits.md](10-v2.9-limits.md)

İddia: completed investigation process restart sonrası yeniden açılır. Bu bir database migration değildir.

```text
User → FastAPI → run_investigation() → InvestigationState → store → data/processed/runs/<run_id>.json
```

Engine (`analysis/graph.py`) persistence detayını bilmez.

---

## Depolama

`analysis/store.py`: `save_run` / `get_run` / `list_runs`. JSON + `os.replace`.

```text
data/processed/   # veya EVIDRA_DATA
├── uploads/
├── datasets/<dataset_id>.json
├── chats/<chat_id>.json
└── runs/
    ├── <run_id>.json
    └── index.json
```

Canonical run alanları korunur (`id`, `evidence`, `claims`, `reviews`, `traces`, `investigation_report`, …). Paralel state modeli yok.

Status türetilir: `running | completed | failed | abstained` (mevcut `decision` / `error` / `stop_reason`). Terminal kayıt immutable.

Dataset referansı `path_ref`: proje köküne göreli, veya `EVIDRA_DATA` altı için `data-root:` öneki. Absolute path mümkün olduğunca yazılmaz.

Index yalnızca metadata. `GET /runs` dosyaları tarar ve index’i yeniden yazar. Bozuk index sessiz boş liste olarak kullanılmaz; run JSON’larından yeniden kurulur. Bozuk run JSON listeden atlanır; `GET /runs/{id}` 422 verir (boş run uydurulmaz).

---

## API

| Durum | HTTP |
| --- | --- |
| Run yok | 404 |
| Run JSON bozuk | 422 |
| Dataset kaydı yok | 404 |
| Dataset JSON bozuk veya dosya yok | 422 |

Restart sonrası `GET /runs/{id}` diskten okur; investigation yeniden çalışmaz. Report persisted `investigation_report` veya aynı frozen state’ten `build_investigation_report`.

Chat: `last_run_id` + mesajlar lokal JSON. Auth yok.
